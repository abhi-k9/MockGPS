# CI cost control and persistent signing

Use [FAST/CHECK locally](DEVELOPMENT.md) before pushing a coherent milestone. Feature branches validate via PR only, master via push. Dependency Review has its own concurrency cancellation and still fails on high/critical. Android planning/source/Tasker checks are cheap and always visible. A canonical app/build/harness fingerprint may reuse completed matching proof for PR feedback; known failures stay blocked, unreadable evidence schedules validation, and forks cannot supply trusted proof. Newest job-attempt selection and attempt-specific artifact names support failed-job-only retries.

Ordinary relevant PR changes run debug assembly, all JVM, lint and API36. They omit release assembly. The API37 job currently fails immediately with the saved infrastructure diagnosis, without another identical cold boot; this temporary hold stays visible. `force_android=true` is an explicit FULL dispatch, performing clean debug/unsigned release/all-JVM/lint/test packaging and actual API36+37 execution. Retry it only after a reviewed runner/image/harness change, or when release gates require new adequate evidence. Both APIs must actually pass for release. There is no skip-to-green conversion. Disposable artifacts retain7days; release assets and committed receipts are not subject to that expiry.

The measured prior three expensive jobs took166+350+245=761runner-seconds. Two observed later plan-only runs took12/10s and skipped all6 expensive jobs. At those historical durations, the avoided repeated work is approximately25.4runner-minutes; this is a bounded comparison, not an invoice. Separate emulator jobs still compile their own APKs; a new cross-job artifact-install architecture was not justified without end-to-end provenance/harness tests. SDK download reuse on trusted local machines is retained. Hosted PR homes remain isolated and setup-gradle cache disabled.

Signing is a manual, noncancellable, separate job, using only the four authorized repository secret bindings. No PR/build/plan step binds them. Only sign-release has contents:write; it can update one matching **draft prerelease**, with no publish/merge operation. Preparation has no signing secrets. Both scripts require successful exact-source full validation, actual complete API36+37 annotations and exact-SHA Dependency Review action success. Checkout, workflow SHA and APK source must be identical; runtime/tree equivalence is insufficient for release. The old API37 infrastructure exception is removed. Certificate identity is pinned in ci/release-policy.json to the independently verified authorized signer. A changed signer fails rather than silently breaking upgrades.

The temporary key is mode600 outside assets, tool errors suppress sensitive arguments/URLs, passwords are environment references, and the key is deleted before upload. APK alignment, nondebug manifest/package/version/target, signature, asset checksums and uploaded digests are checked. No new signing key or debug substitution is used. A new candidate requires fresh reviewed advisory provenance; signed assets retain exact source archives, bounded SBOM and raw scan limitations.

Historical signing run40069442731 successfully produced the earlier private APK despite the explicitly recorded API37 blocker. That receipt is preserved as history; it does not satisfy the tightened current gate or describe later source changes. The existing draft stays targeted to that historical candidate, and its assets must not be relabelled as current HEAD. Future RELEASE preflight (`VALIDATION_RUN_ID=... scripts/dev.sh release`) never dispatches, builds, reads private keys or publishes. Only after exact automated gates pass should the isolated manual signing job be invoked; publication also needs applicable physical safety evidence and explicit review.

## Historical draft metadata repair

Final asset verification found the signing tool created an optional `.apk.idsig` v4 sidecar and listed it in manifest/checksums, but the upload list omitted it. Embedded APK signatures remain valid. A narrowly pinned manual `repair-draft-metadata` job can remove **only** that known missing entry from the historical draft manifest/SHA256SUMS, preserving the APK/source/receipt bytes and recording original metadata hashes. It binds no signing credentials, provisions no SDK, builds nothing, cannot publish, and shares the noncancellable draft-write concurrency group. Other missing/mismatched assets or a different source/APK fail closed. Future signing explicitly disables v4 sidecar generation. Original metadata is archived under evidence/beta; the repaired root manifest remains the historical APK's manifest, not a new-source binary claim.
