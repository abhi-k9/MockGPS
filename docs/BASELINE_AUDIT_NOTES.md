# Baseline audit working evidence

Baseline: `2a2e4322596dcb2b37327999dce3f0d079d35dea` (before hardening). Inspected every Kotlin source file (3,217 lines), manifests, resources, Gradle settings/wrapper, backup samples, README and GPL-3.0 license. Line references below are baseline references, not references into subsequently refactored code. This is source-analysis evidence; no exploit was executed on physical hardware. Final remediation status belongs in `AUDIT.md` after implementation and validation.

## Platform, dependency, privacy and release observations

- The app uses ordinary `LocationManager` test-provider APIs. `Location` wall-clock and `elapsedRealtimeNanos` are set (`MockLocationService.kt:506-511`). No attempt to clear mock flags, bypass third-party detection, root or Shizuku was found. It controls named `gps` and `network` providers, not every fused/cache/vendor location source.
- Foreground notification channel is LOW and service declares `foregroundServiceType=location`. Runtime location and notification permissions are requested; mock-app selection checked by visible activity only. No ACCESS_BACKGROUND_LOCATION permission exists, so background automation cannot assume while-in-use eligibility. Platform research must decide permitted startup and user-initiated fallback.
- Main manifest disables backup (`allowBackup=false`). Unused backup/data-extraction sample files contain permissive TODOs and are not referenced. Android/OEM device-transfer handling merits explicit restrictive data-extraction policy for eventual capability credentials; it is not evidence that backups currently leak.
- Existing map uses HTTPS OpenFreeMap Liberty style (`MainActivity.kt:752-754`). Tile/style/glyph requests disclose user IP and viewed geographic area to the tile provider; camera position is retained in private map preferences (`633-665`). No application analytics, tracking SDK, network command server, arbitrary URL fetch, shell execution, sensitive Log call or location history database was found in app source. Library runtime behavior was not packet-captured.
- SDK logo/attribution UI is disabled (`744-748`), but drawer attribution already credits OpenStreetMap/OpenFreeMap/MapLibre (`activity_main.xml:339`); do not report missing attribution or a proven license violation. Preserve and review required linked/visible attributions with provider terms.
- Merged debug manifest includes INTERNET, ACCESS_NETWORK_STATE and ACCESS_WIFI_STATE from dependencies, even though source main manifest lacks those entries. Review whether WIFI_STATE can be removed through manifest merge while retaining map behavior. Network and notification permissions should be documented.
- Active dependencies are fixed literals: core-ktx 1.17.0, activity-ktx 1.10.1, drawerlayout 1.2.0, MapLibre 13.6.1; AGP 9.2.1 and Gradle 9.6.0. Unused version catalog contains different versions and Compose entries, creating maintenance ambiguity, not a confirmed vulnerability. No vulnerability scan result is available from baseline analysis; do not invent CVEs.
- Gradle wrapper distribution has a pinned SHA-256; TLS verification preserved in setup. No dependency locking/verification metadata exists. No private signing key or credentials tracked. Release configuration disables minification and has no release signing config; absence of obfuscation is not a security vulnerability. Debug APK is not a production signing artifact.
- GPL-3.0 LICENSE and upstream copyright are present. Preserve license/copyright, include corresponding source when distributing binaries, and document fork changes. No third-party implementation code needs copying for hardening.

## Negative findings and limits

No confirmed caller impersonation through package extras exists because baseline does not attempt caller authentication at all. No proof of thread-level data race is asserted: Android component callbacks and handler execute on the main thread in one process, but state transitions spread across components and queued commands can still be contradictory. Atomic coordinate preference writes use one editor commit; public setters nevertheless do not validate their inputs. Broadcast parsing validates finite/range coordinate values; this validation should be retained in the shared domain layer.

No Samsung One UI 9, Android 17 emulator or physical-device lifecycle test was performed by this review. Reliable genuine-location reacquisition, process-death cleanup, OEM battery restrictions and background Tasker eligibility remain runtime validation topics, not source-proven guarantees.
