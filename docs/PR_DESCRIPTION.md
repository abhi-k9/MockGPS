# Harden MockGPS controls and repair Android development CI

The upstream exported command interface allowed unrelated applications to change simulation without authentication. This branch makes the service private, replaces that interface with opt-in capability authentication, and separates requested policy, observed service state and provider cleanup. It also fixes the SDK bootstrap and incomplete strict-verification metadata that prevented the initial implementation from passing CI.

AUTO, FORCE_REAL and explicit MANUAL_MOCK share one serialized controller. FORCE_REAL persists until explicitly cleared by the user. Car connection or unknown state cancels pending activation; disconnection requests visible confirmation after the configured delay. A native Quick Settings tile controls the override. Neither a Tasker broadcast nor a tile callback is treated as an unconditional background location foreground-service exemption.

The independent follow-up review fixed two confirmed correctness defects: event timestamps no longer double as replay ordering, so same-millisecond events and clock adjustments cannot corrupt ordering; service callbacks retain unresolved legacy-provider cleanup state. API2 uses exact Android extra types, a separate persisted sequence, freshness checks and credential rotation. Status does not consume mutation ordering. Provider ownership journaling, partial-initialization rollback, revocation and repeated cleanup remain explicit; stopping injection is never represented as proof of a fresh genuine fix. Credentials and genuine coordinates are excluded from diagnostics and backups.

## Remaining gates

[Dependency review](https://github.com/abhi-k9/MockGPS/actions/runs/40027632842) remains visibly failed: GitHub reports that dependency review is unsupported for this repository and asks for Dependency graph configuration. The repository is public; the integration's administrative API returns403, so it cannot repair the setting. The owner must check/enable Dependency graph in repository settings and rerun the check. This is an external feature/permission blocker, not a successful advisory scan; the workflow was not disabled or made permissive.

Samsung One UI9/Android17, real Tasker delivery, specific-car Bluetooth, secure lock-screen behavior, process/reboot recovery and genuine-fix reacquisition require physical-device evidence. All22 Samsung cases remain NOT RUN; the prioritized12-step sequence provides expected results and redacted diagnostics. API36 emulator success does not establish Android17 or Samsung compatibility. Android's background-start and location-permission gates are separate; conditional supported exemptions do not guarantee unattended operation with this architecture, so visible confirmation is retained.
