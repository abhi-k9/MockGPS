# MockGPS Beta EXPERIMENTAL Tasker project

**Actual Tasker import and phone behavior: NOT RUN.** This is an experimental standalone `.prj.xml` sample, not a phone-tested integration. No Tasker app/device is attached to this environment. The XML's Java Function layout is compared with a real captured MIT-licensed export; other action argument IDs/types are compared with recorded Tasker definition facts. See `fixtures/schema-facts.json` and the adjacent MIT notice. No root/plugin/ADB-at-runtime action is included. No other project's executable behavior was copied.

The project contains selected-car BT Connected enter/exit, Bluetooth-off, monitor-start and boot profiles; one mutation dispatcher; manual reconciliation, UNKNOWN-test, status, stop and setup-help tasks. The selected display name is **Sportage Hybrid**. No MAC is invented. Every profile has a `%MockGPSReady = 1` context and the sender independently checks it. Imports initialize no globals, token or counter. On boot/monitor recovery it sends UNKNOWN rather than trusting a possibly stale disconnected result; reconcile current state explicitly afterward.

## Timestamp ordering and integration independence

`STALE_VEHICLE_OBSERVATION` means a disconnected query predates (or ties) newer connected/unknown information, even if its counter is higher. Reconcile the current car state again; do not change the timestamp on an old queued event. Clock rollback can temporarily block disconnected requests; safety stops and FORCE_REAL remain available. The Tasker switch retains explicit existing consent and counters across an app upgrade; revoke/new token is a deliberate new epoch. The separate Samsung switch is unavailable and cannot become a second sender.
